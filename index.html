The story

Garur was born out of frustration. Every modern CSS tool required a Node process, a plugin chain, and a build that got slower as the codebase grew. I wanted something simpler — a compiler that felt native, that read like a designer's intent, that shipped zero JavaScript to the browser.

So I wrote it in Rust. Three semantic layers — signature, primitive, utility — fused into one binary. A palette of 343 handcrafted colors, CVD-tested. A build that runs in single-digit milliseconds.

FAQ

Questions?
Answered.

What makes Garur different? +

Garur is a semantic hybrid — three layers (signature, primitive, utility) fused into one native Rust engine. It reads like a designer's intent, compiles like a systems binary, and ships zero JavaScript to the browser. Not a wrapper around anything.

Do I need Node.js installed? +

Yes — for the npm package and CLI. But the engine itself is a prebuilt native binary distributed via N-API. No compilation step, no plugin chain, no JavaScript runtime in your browser.

How fast is it really? +

On an M1 MacBook Pro, Garur compiles 10,000 unique utility classes in roughly 30 milliseconds cold, and around 3 milliseconds warm. The bottleneck is disk I/O, not the compiler. Compare to Node-based pipelines which typically take 850ms to 1.2 seconds.

Does it work with my framework? +

Yes. Garur ships a CLI plus integrations for Vite, Next.js, Webpack, Rspack, and Nuxt. The engine is framework-agnostic — anything that consumes a CSS file works with Garur.

Can I customize the palette? +

Absolutely. Every family, shade, and token is defined via --garur-* CSS variables. Override at runtime, at build time, or through the garur.config.js file — no rebuild required for theme changes.
