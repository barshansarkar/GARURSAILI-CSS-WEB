The architecture

Three layers.
One engine.

Most frameworks make you choose between semantic classes and atomic control. GarurSaili gives you both — the same vocabulary stack holds three different ways of thinking, and they compose without compromise.

01 signature.rs

Intent layer

Semantic classes that read like descriptions. Instead of remembering flex items-center justify-between, you write apart-mid. Instead of a lift-shadow transition, you write hover:lift.

mid apart-mid rise clickable namaste
02 primitives.rs

Primitive layer

Component-level shorthands. card-glass gives you a complete translucent surface with border, radius, padding, and backdrop blur in one class. Every value reads from a --garur-* CSS variable — retheme at runtime, no rebuild.

card btn-primary navbar modal alert
03 utilities.rs

Utility layer

5,000+ atomic utilities. The familiar syntax you know — p-4, bg-iris-500, grid-cols-3, hover:rise. Full variant support, arbitrary values, and 21 opacity steps on every color.

p-4 bg-iris-500/50 grid-cols-3 md:dark:hover:rise
composition

All three, in one line of markup.

Layers don't conflict — they fold. Utilities win the cascade where they overlap, so card p-2 overrides the card's default padding without any !important or selector tricks.

card.html 
<!-- intent + primitive + utility, one string -->
<div class="mid card-glass p-8 stack-4 hover:lift">
  <h2 class="headline gradient-text">
    Ship faster.
  </h2>
  <p class="lead text-graphite-600">
    Compile like you mean it.
  </p>
</div>

Ferrous core

Written in Rust.
Compiled to native.

The engine is a single .node binary — no JavaScript bridge, no WASM, no plugin chain. Parse, transform, emit. One pass. Every cache is lock-free. Every rule is an Arc<str>.

Warm rebuild
3 ms

Average warm rebuild latency across 10,000 unique classes. Cold cache: ~30ms. The bottleneck is disk I/O, not the runtime.

pub fn build(cls: &str) -> Option<Arc<str>> {
  if let Some(v) = BUILD_CACHE.get(cls) {
    BUILD_HITS.fetch_add(1, Relaxed);
    return v.clone(); // O(1) Arc clone
  }
  build_inner(cls)
}

Authoring

A full CSS toolkit.

Garur doesn't stop at utility classes. Define tokens in CSS, extract reusable patterns with @apply, register plugins in JS, and query the size of any container — all with the same engine.

@theme CSS-native config

Design tokens, where they belong

Declare colors, spacing, radius, and fonts inside a @theme block. The engine extracts them, feeds them to the same pipeline as garur.config.js, and generates utilities automatically.

theme.css 
@theme {
  --color-brand-500: #f97316;
  --spacing-gutter: 2rem;
  --radius-card: 1.25rem;
}

/* Generates: bg-brand-500, p-gutter, rounded-card */
@apply variant-aware

Extract patterns into classes

Perfect for markdown, CMS content, and third-party widgets. @apply accepts variants too, and folds them into nested CSS at build time.

components.css 
.callout {
  @apply p-4 rounded-lg border
         hover:rise focus-visible:ring-2;
}

.callout-info {
  @apply bg-sky-50 border-sky-200;
}
@container named containers

Responsive to the container, not the viewport

Build components that adapt to their slot — sidebar, card, article — using @sm: through @3xl:. Named containers let you have independent responsive contexts in the same tree.

sidebar.html 
<aside class="@container/sidebar">
  <h3 class="text-sm
       @lg/sidebar:text-lg">
    Grows only when the sidebar is wide
  </h3>
</aside>
plugin.js JS API

Register your own utilities & variants

Two functions. That's the entire plugin API. Custom utilities and variants merge into the same namespace as the built-in ones — and they can never override existing classes.

plugin.js 
import {
  registerPluginUtility,
  registerPluginVariant
} from 'garursaili-css';

registerPluginUtility(
  'glass',
  'backdrop-filter:blur(16px)'
);

registerPluginVariant(
  'hocus',
  '&:hover, &:focus-visible'
);
semanticColors: true

FAQ

Questions,
answered.

What makes GarurSaili different from other CSS frameworks?

Three things. First — the engine is native. A single Rust binary, no JavaScript runtime. Second — the vocabulary is hybrid: intent classes, component primitives, and atomic utilities compose without conflict. Third — the palette is poetic and original: 31 families named after the world we see, not the alphabet. Nothing here is a wrapper.

Does it work with my framework?

Yes. Garur emits plain CSS — anything that consumes a stylesheet works with it. The docs include guides for Next.js, Vite, and plain HTML. The engine is framework-agnostic; it only cares about your source files.

Do I need a Rust toolchain installed?

No. The npm package ships prebuilt native binaries for Linux (x64, arm64, musl), macOS (Intel, Apple Silicon), and Windows (x64). Installation is a normal npm command — no compilation step.

How fast is it, really?

On an Asus ROG Strix(intel core i5 9th gen without any gpu ), Garur compiles 10,000 unique utility classes in roughly 30 milliseconds cold and about 3 milliseconds warm. Cache hit rate on warm rebuilds is above 99%. The bottleneck is disk I/O, not the engine.

Can I customize the palette?

Yes — three ways. (1) Runtime tokens: override --garur-* CSS variables on :root. No rebuild. (2) Config palette: add custom families in garur.config.js — the engine generates the full utility set. (3) Semantic layer: opt in with semanticColors: true to get role-based tokens like bg-primary.

Is there a VS Code extension?

Yes. The GarurSaili IntelliSense extension adds autocomplete, hover documentation, class sorting, and diagnostics for VS Code, Cursor, Windsurf, and any editor based on the VS Code API. Search "GarurSaili" in the extensions marketplace.

What is the license?
