Docs / Foundation

Foundation

Preflight, runtime tokens, and the accessibility defaults that ship with every Garur build. This is the layer beneath your styles — resets, sensible defaults, and the CSS variables that make retheming possible.

3 sections
· Zero JS shipped

Preflight

Preflight is Garur's baseline stylesheet. It's emitted first, wrapped in cascade layers, and includes everything you'd otherwise write by hand at the top of every project: box-sizing, margin resets, focus rings, form normalization, print styles.

Every section is optional. Pass getPreflightConfigured({ print: false, a11y: true }) to toggle individual blocks. Perfect for embedding Garur into existing projects without fighting your own resets.

Cascade layers

Everything Garur emits lives inside declared layers. This means your own CSS — outside any layer — always wins, without needing !important.

layer order 
@layer garur-tokens, garur-reset, garur-elements,
       garur-forms, garur-motion, garur-utils;

/* Later layers win over earlier ones. */
/* Your own unlayered CSS wins over all of them. */

Configuring Preflight

enable print + dark_auto 
import { getPreflightConfigured } from 'garur';

const preflight = getPreflightConfigured({
  print: true,
  dark_auto: true,
  auto_dark_controls: true,
  reduced_data: false, // skip data-saver
});

Accessibility

Garur ships accessible defaults. Focus rings, reduced-motion, high-contrast, forced-colors, and reduced-data are all baked in — no opt-in classes, no per-component configuration.

Focus management

Preflight sets a visible focus ring on :focus-visible globally and removes it for mouse-only focus. This means every interactive element has an accessible focus indicator by default — buttons, links, inputs, and anything with tabindex.

Live demo — focus ring

Reduced motion

When the OS reports prefers-reduced-motion: reduce, Garur collapses all animations and transitions to 0.01ms globally. Your animate-spin classes stay in the stylesheet but become visually static.

built into preflight 
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

Forced colors

Windows High Contrast mode overrides your colors. Garur's preflight ensures focus rings and dialog borders still work in forced-colors mode, and forced-color-adjust-none is available for the rare case where you need to opt out.

forced-color-adjust-auto forced-color-adjust-none sr-only not-sr-only

Color vision deficiency

The 31-family palette was tested against 8 CVD simulations. Every pair used by a semantic utility (primary/danger, success/warning) maintains a perceivable difference under deuteranopia, protanopia, and tritanopia. Semantic colors are additionally separated by lightness, not just hue.

Never rely on hue alone. For status indicators, pair the color with an icon or text. The tag-ok / tag-err shorthands use both color and a foreground tint so they remain distinguishable without hue.

Screen reader support

Utility Purpose
sr-onlyVisually hidden but readable by assistive tech
not-sr-onlyReverts the above (e.g. on focus)
forced-color-adjust-noneOpt out of forced-colors overrides
Docs / Configuration

Configuration

Garur is zero-config by default. When you need to customize, create garur.config.js at the project root and provide only the keys you want to override. Everything else inherits sensible defaults.

garur.config.js

full config 
export default {
  content: ['./src/**/*.{html,tsx,jsx,vue,svelte}'],
  output: './build/garur.css',

  darkMode: 'class',          // 'class' | 'media'
  important: false,           // force !important on every utility

  breakpoints: {
    sm:  '640px',
    md:  '768px',
    lg:  '1024px',
    xl:  '1280px',
    '2xl': '1536px',
  },

  palette: {
    brand: {
      50:  '#fff7ed',
      500: '#f97316',
      900: '#7c2d12',
    },
    accent: '#8657f7',       // single-value color
  },

  semanticColors: false,       // opt-in layer
  semanticOverrides: {
    primary: '#c2410c',
    'warning-fg': '#422006',
  },

  targets: ['> 0.5%', 'last 2 versions', 'not dead'],
};

Keys

Key Type Description
contentstring[]Glob patterns for source files to scan
outputstringWhere to write the compiled CSS
darkMode'class' | 'media'How dark: variant resolves
importantbooleanForce !important on every declaration
breakpointsobjectResponsive breakpoint names → widths
paletteobjectCustom colors merged with the 31 default families
semanticColorsbooleanGenerate bg-primary etc. — off by default
semanticOverridesobjectCustom colors for semantic roles
targetsstring[]Browserslist queries for LightningCSS transformation

Loading order

The CLI loads garur.config.js from the current working directory, deep-merges it with defaults, and passes the result to the native engine via initConfig. The config is applied once per process — restart the watcher after editing it.

Merge semantics. Palette merges shade-by-shade: { brand: { 500: '#xyz' } } overrides only shade 500 of a family, keeping 50–900 intact. Breakpoints shallow-merge, so providing { md: '800px' } only changes md.

Editor setup

Garur ships first-class editor support. Autocomplete, hover docs, class sorting, and TypeScript types for the config file are all available.

TypeScript config types

garur.config.js is fully typed. Enable JSDoc-based IntelliSense by naming the file with a leading /** @type */ annotation, or convert to TypeScript.

garur.config.js (typed) 
/** @type {import('garursaili-css').GarurConfig} */
export default {
  darkMode: 'class',
  palette: {
    brand: { 500: '#f97316' },
  },
};

Prettier plugin

Automatic class sorting. The plugin groups classes in the same order the engine emits them: layout, position, spacing, sizing, typography, colors, effects, interaction — then variants last.

.prettierrc 
{
  "plugins": ["prettier-plugin-garur"],
  "garurSortClassList": true
}

CLI formatter

If you don't use Prettier, the CLI has a built-in formatter that sorts class attributes across all markup files:

Docs / Authoring

Authoring

Everything related to writing CSS alongside your markup — theme blocks, apply directives, container queries, and plugins. This is the layer where Garur becomes a full CSS toolkit rather than just a class generator.

@theme & @apply

@theme

Declare design tokens directly in CSS. Garur extracts them, feeds them into the engine as if they were in garur.config.js, and emits them as CSS custom properties on :root. This lets you keep colors and spacing near the components that use them.

theme.css 
@theme {
  --color-brand-50:  #fff7ed;
  --color-brand-500: #f97316;
  --color-brand-900: #7c2d12;

  --spacing-xs: 0.125rem;
  --spacing-xl: 2rem;

  --radius-card: 1.25rem;
  --font-brand: "Inter Variable";
}

/* After extraction, these are also available as utilities: */
/* bg-brand-500, text-brand-900, p-xs, p-xl, rounded-card, font-brand */

The engine writes the extracted tokens back as CSS variables so they're available at runtime:

compiled output 
:root {
  --color-brand-50:  #fff7ed;
  --color-brand-500: #f97316;
  --color-brand-900: #7c2d12;
  --spacing-xs: 0.125rem;
  --radius-card: 1.25rem;
  --font-brand: "Inter Variable";
}

@apply

Extract utility strings into named classes. The engine expands @apply at build time — the emitted CSS contains the resolved declarations, not a reference.

components.css 
.callout {
  @apply p-4 rounded-lg border border-graphite-200 dark:border-white/10;
}

.callout-info {
  @apply bg-sky-50 border-sky-200 text-sky-900;
}

.callout-title {
  @apply headline mb-1;
}

/* @apply accepts variants too */
.btn-hover-lift {
  @apply hover:rise focus-visible:ring-2 focus-visible:ring-iris-500;
}

Variants inside @apply compile into the nested selector form:

compiled output 
.btn-hover-lift { }
.btn-hover-lift:hover { box-shadow: var(--garur-shadow-lg); }
.btn-hover-lift:focus-visible {
  --garur-ring-width: 2px;
  --garur-ring-color: #8657f7;
  box-shadow: 0 0 0 2px #8657f7;
}

When to use @apply

Good use
  • Markdown-rendered content you don't control
  • CMS blocks and rich-text output
  • Third-party widgets that need one class
  • Styles for :has() child selectors
Bad use
  • Component class strings in JSX
  • Anything used once
  • Replacing a primitive that already exists
  • Bundling unrelated utilities into "utility soup"

Container queries

Container queries respond to the size of a container element rather than the viewport. This is the modern way to build components that adapt to their slot, not their page.

Declaring a container

Apply @container to the element whose width you want to measure. Descendants can then use @sm:, @md:, etc. to respond.

basic container 
<div class="@container">
  <div class="grid grid-cols-1 @md:grid-cols-2 @lg:grid-cols-3">
    <!-- Columns switch based on the *container* width,
         not the viewport -->
  </div>
</div>

Live demo — resize the box

Drag the resize handle at the bottom-right of the container below. The card inside reflows based on the container width, not the viewport.

Named containers

Use @container/{name} to give a container a name. Then @md/{name}: on descendants resolves against that specific ancestor — even when there are nested containers.

named containers 
<aside class="@container/sidebar">
  <h3 class="text-sm @lg/sidebar:text-lg">
    Grows only when the sidebar is ≥ 32rem
  </h3>
</aside>

<article class="@container/article">
  <h1 class="text-2xl @md/article:text-4xl">
    Independent of the sidebar
  </h1>
</article>

Plugins

Garur's plugin API is minimal by design. Register custom utilities and custom variants from JavaScript — they merge into the engine's namespace and are available to every scan, build, and SSC pass.

Registering utilities

plugin.js 
import { registerPluginUtility } from 'garursaili-css';

// Simple: name → declarations
registerPluginUtility(
  'glass',
  'backdrop-filter:blur(16px);background:rgba(255,255,255,0.6);border:1px solid rgba(0,0,0,0.08)'
);

registerPluginUtility(
  'focus-ring',
  '&:focus-visible { outline:2px solid currentColor; outline-offset:2px; }'
);

// Now `glass` and `focus-ring` are valid classes
// everywhere — including under variants like `hover:glass`

Registering variants

variant-plugin.js 
import { registerPluginVariant } from 'garursaili-css';

// Custom variant: `hocus` = hover OR focus
registerPluginVariant(
  'hocus',
  '&:hover, &:focus-visible'
);

registerPluginVariant(
  'portrait-print',
  '@media (orientation: portrait) and print'
);

// Now `hocus:bg-iris-500` and `portrait-print:...` work everywhere

Introspection

Function Returns
listPluginUtilities()JSON array of [name, declarations] pairs
listPluginVariants()JSON array of [name, template] pairs
clearPlugins()Removes all registered plugins
Plugin utilities never override built-ins. Registration uses or_insert_with. If a utility with the same name already exists in the base engine, yours is silently ignored. This means adding plugins is always safe — you can't break existing classes.

Example — build a component

api-usage.js 
import {
  initConfig,
  buildBatch,
  runSsc,
  getCacheStats,
} from 'garursaili-css';

// Configure the engine once
initConfig(JSON.stringify({
  darkMode: 'class',
  palette: { brand: { 500: '#f97316' } },
}));

// Build a batch of classes
const rules = buildBatch([
  'mid',
  'card-glass',
  'hover:rise',
  'bg-brand-500',
]);

// Or run a full SSC pass on files
const css = runSsc(
  ['./app/page.tsx', './app/layout.tsx'],
  JSON.stringify({ darkMode: 'class' })
);

// Inspect cache performance
const stats = getCacheStats();
console.log(stats.build_hit_rate); // 99.4

Browser support matrix, target resolution, and the version history. Everything you need to know about what Garur produces and when.

Browser support

Garur compiles to modern CSS. Properties that a target browser doesn't support are handled by LightningCSS at build time — either transformed into a compatible form or silently dropped if there's no fallback.

Default targets

Browser Minimum version
Chromelast 2 versions
Firefoxlast 2 versions
Safari16+
Edgelast 2 versions
iOS Safari16+
Samsung Internetlast 2 versions

Feature availability

Feature Baseline Handling
CSS Nesting2023Flattened for older targets
Cascade Layers2022Preserved — supported everywhere we target
color-mix()2023Pre-computed at build time when palette value is known
:has()2023Emitted as-is — no fallback possible
Container queries2023Emitted as-is — no fallback
View transitions2024Emitted as-is — ignored on old browsers
Anchor positioning2024Emitted as-is
oklch()2023Used only in a few advanced utilities
:focus-visible2022Preserved — no fallback needed
backdrop-filter2022Prefixes added for older Safari

Customizing targets

Targets are browserslist queries. Set them in garur.config.js and LightningCSS will transform accordingly.

garur.config.js 
export default {
  // Support older browsers → larger output, more polyfills
  targets: ['> 0.5%', 'last 3 versions', 'not dead'],

  // Or modern-only → smallest output, no fallbacks
  // targets: ['last 1 Chrome version', 'last 1 Safari version'],
};
