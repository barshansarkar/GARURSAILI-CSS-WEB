Introduction to GarurSaili

GarurSaili-CSS is a semantic hybrid CSS engine. It fuses three layers — intent, primitive, and utility — into a single native Rust binary that compiles at the speed of disk I/O.

Stable · v1.4.1
·
MIT licensed
· Built in Malda, West Bengal
Section 01 · Introduction

What is GarurSaili?

GarurSaili is a compiler. You write class names in your markup, point it at your source files, and it emits exactly the CSS you use — nothing more, nothing less. There is no runtime, no plugin chain, and no JavaScript shipped to the browser.

What makes it different is that its vocabulary spans three layers of abstraction. You can write mid to mean "center on both axes" without remembering whether that's flex or grid. You can write card-glass and get a complete translucent surface with border, radius, shadow, and backdrop blur in a single class. You can also write raw utilities like p-4 and bg-iris-500 when you need precise control.

All three coexist. Compose them together. The engine handles the rest.

ग
गरुड़ · garuḍa
Sanskrit · "eagle"

The garuḍa was the mount of Lord Vishnu — a divine eagle said to be the fastest creature in the sky, faster than the wind itself. We named this framework after it because speed should not be a compromise. GarurSaili compiles 10,000 classes in thirty milliseconds — not by trading precision for speed, but by refusing to accept that they are opposites.

Build-time only.

GarurSaili has zero effect on your application's runtime bundle. The output is a plain CSS file — no CSS-in-JS, no injected style tags, no runtime style computation, no JavaScript shipped to the browser.

Section 02 · Installation

Installation

GarurSaili is distributed as a prebuilt native binary via N-API. Installation does not require a Rust toolchain, a build step, or any native compilation on your machine.

recommended
npm
Cross-platform

Prebuilt binaries for Linux, macOS, and Windows.

CDN
Zero-install

Prebuilt garur.min.css via jsDelivr.

VS
Editor

IntelliSense for VS Code and Cursor.

Install via npm

terminal 
$ npm install garursaili-css

Works with npm, pnpm, Yarn, and Bun without configuration. The package ships precompiled binaries for macOS (x64, arm64), Linux (x64, arm64), and Windows (x64).

Or use the CDN

Drop one <link> into any HTML page. The whole preflight, palette, primitives, and utilities are available immediately.

index.html 
<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/npm/garursaili-css/dist-cdn/garur.min.css" />

Verify installation

terminal 
$ npx garur --version
garursaili-css/1.4.1
native/ferrous-engine
platform/linux-x64-gnu
Editor extension. Search "GarurSaili" in the VS Code marketplace for autocomplete, hover docs, class sorting, and diagnostics. Works in Cursor and Windsurf too.
Section 03 · Quick start

Quick start

The fastest way to see GarurSaili work is with the built-in ssc command — Super Sonic Cyclone. It scans your source files, extracts every class, and emits a single stylesheet in one pass.

1. Scan and build

terminal 
$ npx garur ssc ./src
✓ Scanned 124 files
✓ Extracted 842 unique classes
✓ Built in 28ms
→ ./build/garur.css · 14.2 KB

2. Link the stylesheet

index.html 
<link rel="stylesheet" href="./build/garur.css" />

3. Write classes

page.html 
<div class="mid stack-4 p-8">
  <h1 class="text-3xl font-bold">Hello</h1>
  <button class="btn btn-primary">Get started</button>
</div>
Section 04 · Core concept

Three layers

GarurSaili's vocabulary is organized into three layers. Each has a distinct purpose. Understanding them helps you decide which class to reach for when.

1

Intent layer

signature.rs

Describes what you mean using vocabulary that maps to your mental model. mid means "centered both axes." apart-mid means "space-between, aligned." rise means "elevated with a shadow."

mid apart-mid rise clickable namaste
2

Primitive layer

primitives.rs

Component-level shorthands powered by runtime tokens. card gives you a complete surface with border, radius, padding, and shadow. btn gives you a button skeleton. Every token is a CSS variable, so theming works at runtime.

card btn-primary navbar modal alert
3

Utility layer

utilities.rs

Atomic utilities with a familiar syntax — p-4, bg-iris-500, grid-cols-3, hover:rise. Full variant support, arbitrary values, and opacity modifiers.

p-4 bg-iris-500/50 grid-cols-3 md:dark:hover:rise
Layers compose freely. There is no rule preventing you from mixing a primitive with utilities, or using an intent alongside raw atomic classes. Utilities win the cascade where they overlap, so card p-2 overrides the card's default padding without any !important.

Section 06 · Primitive layer

Primitive layer

Primitives are complete component shorthands. Every primitive reads its values from --garur-* CSS variables, which means you can retheme the entire system at runtime by overriding those variables on :root.

Common primitives

Class Description
cardSurface with border, radius, padding, shadow
card-glassTranslucent surface with backdrop blur
btnButton skeleton — pair with btn-primary
badgeInline pill — variants for each semantic color
alertNotice block with border and background tint
inputForm input with focus ring
navbarTop navigation bar layout

Example — a complete card with header, body, and action buttons:

example.html 
<div class="card">
  <div class="card-header">Title</div>
  <div class="card-body">Content</div>
  <div class="card-footer">
    <button class="btn btn-primary">Save</button>
  </div>
</div>

Primitives include forms, feedback, navigation, overlays, and content components. See the full list in the utility reference →

Section 07 · Variants

Variants

Any utility, primitive, or intent can be prefixed with a variant. Prefixes stack from left to right — md:dark:hover:bg-iris-500 applies on medium screens, in dark mode, on hover.

peer-checked:Sibling with .peer is checked
has-[:checked]:Element matches :has() selector
data-[state=open]:Element has matching data attribute
aria-expanded-true:ARIA attribute is true
motion-safe:Reduced-motion is not preferred
print:Print media
rtl: · ltr:Text direction

Section 09 · Preflight

Preflight

Preflight is GarurSaili's baseline stylesheet. It's emitted first, wrapped in cascade layers, and includes everything you'd otherwise write by hand at the top of every project: box-sizing, margin resets, focus rings, form normalization, print styles.

Every section is optional. Pass getPreflightConfigured({ print: false, a11y: true }) to toggle individual blocks. Perfect for embedding GarurSaili into existing projects without fighting your own resets.

Cascade layers

Everything GarurSaili emits lives inside declared layers. This means your own CSS — outside any layer — always wins, without needing !important.

layer order 
@layer garur-tokens, garur-reset, garur-elements,
       garur-forms, garur-motion, garur-utils;

/* Later layers win over earlier ones. */
/* Your own unlayered CSS wins over all of them. */

Configuring preflight

enable print + dark_auto 
import { getPreflightConfigured } from 'garursaili-css';

const preflight = getPreflightConfigured({
  print: true,
  dark_auto: true,
  auto_dark_controls: true,
  reduced_data: false, // skip data-saver
});
Section 10 · Authoring

@theme & @apply

@theme

Declare design tokens directly in CSS. GarurSaili extracts them, feeds them into the engine as if they were in garur.config.js, and emits them as CSS custom properties on :root. This lets you keep colors and spacing near the components that use them.

theme.css 
@theme {
  --color-brand-50:  #fff7ed;
  --color-brand-500: #f97316;
  --color-brand-900: #7c2d12;

  --spacing-xs: 0.125rem;
  --spacing-xl: 2rem;

  --radius-card: 1.25rem;
  --font-brand: "Inter Variable";
}

/* After extraction, these are also available as utilities: */
/* bg-brand-500, text-brand-900, p-xs, p-xl, rounded-card, font-brand */

@apply

Extract utility strings into named classes. The engine expands @apply at build time — the emitted CSS contains the resolved declarations, not a reference.

components.css 
.callout {
  @apply p-4 rounded-lg border border-graphite-200 dark:border-white/10;
}

.callout-info {
  @apply bg-sky-50 border-sky-200 text-sky-900;
}

/* @apply accepts variants too */
.btn-hover-lift {
  @apply hover:rise focus-visible:ring-2 focus-visible:ring-iris-500;
}

When to use @apply

Good use
  • Markdown-rendered content you don't control
  • CMS blocks and rich-text output
  • Third-party widgets that need one class
Bad use
  • Component class strings in JSX
  • Anything used once
  • Replacing a primitive that already exists
Section 11 · Plugins

Plugins

GarurSaili's plugin API is minimal by design. Register custom utilities and custom variants from JavaScript — they merge into the engine's namespace and are available to every scan, build, and SSC pass.

plugin.js 
import {
  registerPluginUtility,
  registerPluginVariant
} from 'garursaili-css';

// Custom utility — name → declarations
registerPluginUtility(
  'glass',
  'backdrop-filter:blur(16px);background:rgba(255,255,255,0.6)'
);

// Custom variant — hocus = hover OR focus
registerPluginVariant(
  'hocus',
  '&:hover, &:focus-visible'
);

// Now `glass` and `hocus:bg-iris-500` work everywhere
Plugin utilities never override built-ins. Registration uses or_insert_with. If a utility with the same name already exists, yours is silently ignored — meaning adding plugins is always safe.
Section 12 · CLI reference

CLI reference

GarurSaili ships a single CLI binary. Every command accepts a positional path or uses the current directory by default.

garur build — compile stylesheet from config 
$ garur build [--watch] [--minify] [--out ./build/garur.css]
garur ssc — Super Sonic Cyclone · scan, extract, build 
$ garur ssc ./src [--preflight] [--minify]
garur init — scaffold a config file 
$ garur init [--force]
garur benchmark — measure compile performance 
$ garur benchmark --runs 10
garur doctor — diagnose environment 
$ garur doctor
Section 13 · Configuration

Configuration

GarurSaili works with zero configuration. When you need to customize, create garur.config.js at the project root. Only the keys you provide are overridden — the rest inherit sensible defaults.

garur.config.js 
export default {
  content: ['./src/**/*.{html,tsx,jsx,vue}'],
  output: './build/garur.css',

  darkMode: 'class',       // or 'media'
  important: false,
  targets: ['> 0.5%', 'last 2 versions', 'not dead'],

  breakpoints: {
    sm:  '640px',
    md:  '768px',
    lg:  '1024px',
    xl:  '1280px',
    '2xl': '1536px',
  },

  palette: {
    brand: {
      50:  '#fff7ed',
      500: '#f97316',
      900: '#7c2d12',
    },
  },

  semanticColors: false,     // opt-in layer
  semanticOverrides: {
    primary: '#c2410c',
  },
};
