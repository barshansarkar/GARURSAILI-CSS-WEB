Section 01 · Overview

What is an intent?

An intent is a class that names a goal rather than a declaration. It sits above the primitive layer (which names components: card, btn) and the utility layer (which names single CSS properties: p-4, bg-iris-500).

Intents don't take configuration. There are no props, no variants to remember, no nested objects. If you want a different result, you write a different class. The vocabulary is the API.

The utility way
flex items-center justify-between

Three classes, three properties to remember. Works, but reads like a spec.

The intent way
apart-mid

One class, one intent. Reads like a description of the layout.

expansion — what the engine emits 
/* apart-mid */
.apart-mid { display:flex; align-items:center; justify-content:space-between; }

/* rise */
.rise { box-shadow: var(--garur-shadow-lg, 0 10px 15px -3px rgb(0 0 0 / 0.1)); }

/* namaste */
.namaste { display:flex; flex-direction:column; align-items:center;
           text-align:center; padding:3rem 1.5rem; gap:1.5rem; }
Section 02 · Philosophy

Philosophy

Say what you mean

apart-mid is faster to read than flex items-center justify-between, and it describes the same outcome in fewer words. The engine expands the shorthand at build time.

Compose, don't configure

Intents don't take configuration. There are no props, no variants to remember, no nested objects. If you want a different result, you write a different class.

Never override

Every intent is registered with entry().or_insert_with() in the engine. That means an intent never silently overrides an existing class. Adding new intents is always safe — the framework is fully additive.

FAQ

What are intents?

Single classes that expand to a multi-property combination at build time. mid becomes display:flex; align-items:center; justify-content:center.

Can I mix intents with utilities?

Yes. Intents and utilities use the same namespace. Utilities win the cascade where they overlap.
