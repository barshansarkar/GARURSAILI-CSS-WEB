Section 01 · Overview

Why poetic names?

Every framework names its colors after the alphabet — red-500, blue-600, gray-700. That works, but it forces you to remember what a color is before you can decide what it means.

GarurSaili flips the convention. iris is a specific blue-purple flower. plum is a deep pink-purple fruit. ember is the orange of a dying fire. void is the coolest black. You remember the name because you remember the thing — not because you memorized a hex value.

Section 05 · Easy mode

Easy mode

Three shorthand forms reduce typing on common cases. They resolve at build time to the same CSS the explicit form would produce.

bg-iris → bg-iris-500

Omitting the shade resolves to 500, the family's midpoint. Use this for the "default" tone.

same color
bg-iris-6 → bg-iris-600

Single digit expands to the hundreds. 6 → 600, 9 → 900.

same color
bg-iris-95 → bg-iris-950

The only two-digit case is 95 → 950. Single digits already cover 500–900.

same color
Easy mode works with variants. dark:bg-iris-9 expands to dark:bg-iris-900, hover:text-iris expands to hover:text-iris-500.
Section 06 · Semantic colors

Semantic colors — opt-in

Semantic colors map role names to colors. Instead of bg-ruby-600 you write bg-danger. The utility resolves at runtime through a CSS variable, which means the same class changes appearance when you swap themes.

Off by default. Semantic colors require semanticColors: true in your config. When off, these utilities are not generated at all — keeping the output small.

Runtime override

Every semantic utility reads from a CSS variable. Override the variable to change the color without a rebuild — useful for white-labeling, tenant theming, or user-selected accents.

theme.css 
:root {
  --garur-primary: #c2410c;
  --garur-primary-fg: #ffffff;
}

/* Any element using .bg-primary now renders orange. */
/* No rebuild, no class change. */
Section 07 · Custom palette

Adding a brand palette

For brand colors you want to use as utility classes (bg-brand-500, text-brand-600), define them in the config. GarurSaili generates the full shade ramp and every variant automatically.

garur.config.js 
export default {
  palette: {
    brand: {
      50:  '#fff7ed',
      100: '#ffedd5',
      200: '#fed7aa',
      300: '#fdba74',
      400: '#fb923c',
      500: '#f97316',
      600: '#ea580c',
      700: '#c2410c',
      800: '#9a3412',
      900: '#7c2d12',
      950: '#431407',
    },
  },
};

After a rebuild, every color utility has a new variant:

bg-brand-500 text-brand-600 border-brand-300 ring-brand-400 fill-brand-500 from-brand-400 bg-brand-500/50

Custom single colors

You can also add single-value colors without a shade ramp. Just provide the color as a string instead of an object.

garur.config.js 
export default {
  palette: {
    brand: '#6366f1',      // single value
    mystic: '#a855f7',     // another one
  },
};
Section 08 · Runtime theming

Runtime theming

Every primitive reads from a --garur-* CSS variable. That means you can swap the entire color system at runtime — no rebuild, no class changes — by overriding variables on :root. This is how you build multi-tenant UIs, dynamic brand switching, and user-selected accents.

Switch the primary color at runtime

Add a single CSS variable override and every primitive updates — buttons, cards, badges, alerts, modals, the lot. 

/* Change one variable... */
:root {
  --garur-primary: #16a34a;
}

/* ...and every component using the primary
   role updates — instantly, in the browser. */
Or via JavaScript

Useful for user-selected accents, A/B tests, or theme switchers. 

document.documentElement.style
  .setProperty('--garur-primary', '#16a34a');
Section 09 · Accessibility

Accessibility

The 31-family palette was tested against 8 color vision deficiency simulations (deuteranopia, protanopia, tritanopia, and 5 more). Every pair used by a semantic utility maintains a perceivable difference under all three major types. Semantic colors are additionally separated by lightness, not just hue.

✓
WCAG AA

Every foreground/background pair used by a semantic role meets 4.5:1 contrast.

◆
CVD tested

8 simulations, including deuteranopia, protanopia, and tritanopia.

★
Hue + lightness

Semantic pairs are separated by both hue and lightness, so they remain distinguishable without hue.

Never rely on hue alone. For status indicators, pair color with an icon or text. The tag-ok / tag-err shorthands use both color and a foreground tint so they remain distinguishable without hue.
