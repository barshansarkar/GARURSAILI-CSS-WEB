Home / Docs / Variants

Variants 50+ modifiers, one syntax.

A variant is a prefix that changes the conditions under which a utility applies. Write hover:bg-iris-500 and the background only turns iris when the pointer is over the element. Write md:grid-cols-3 and the three-column grid only kicks in at 768px. Variants stack left-to-right, and every utility on the framework accepts every one of them.

Container queries included

Section 01 · Overview

What is a variant?

Every utility can be prefixed with one or more variant tags. The tags are separated by colons and read left to right. hover:bg-iris-500 means "on hover, this element gets the iris-500 background."

The engine reads the variant prefix at build time and wraps the emitted CSS in the right pseudo-class, media query, or attribute selector. Nothing about how the utility itself is generated changes — the variant is purely a wrapper.

Utility alone
bg-iris-500

Always iris-500, at every size, in every state.

With a variant
md:dark:hover:bg-iris-500

Only at md+, in dark mode, while hovered.

expansion — what the engine emits 
/* hover:bg-iris-500 */
.hover\:bg-iris-500:hover { background-color: #8657f7; }

/* md:bg-iris-500 */
@media (min-width: 768px) {
  .md\:bg-iris-500 { background-color: #8657f7; }
}

/* dark:hover:bg-iris-500 */
:where(.dark, .dark *) .dark\:hover\:bg-iris-500:hover {
  background-color: #8657f7;
}
Variants work on every class. Every variant on this page works with every utility, every intent, and every primitive. You can write md:mid, hover:card-glass, or focus-visible:rise without thinking about it.
Section 02 · Stacking

Stacking & order

Variants stack. Write as many as you need, separated by colons. Order matters — the leftmost variant wraps everything to its right.

hover:bg-iris-500
On hover, iris-500 background.
dark:hover:bg-iris-500
In dark mode, on hover, iris-500 background.
md:dark:hover:bg-iris-500
At md and up, in dark mode, on hover.
group-hover:md:dark:text-white
At md and up, in dark mode, when a parent .group is hovered.
md:dark:group-hover:has-[:checked]:text-iris-500
Five levels deep. At md and up, in dark mode, when parent .group is hovered, and this element has a checked child.
Read left-to-right, outwards-in. The variant closest to the utility is the innermost wrapper. The leftmost variant is the outermost. This is why md:dark: reads more naturally than dark:md: — you're describing "at md, in dark mode" not "in dark mode, at md."

Section 04 · Interaction

Interaction variants

Every one of these is a CSS pseudo-class under the hood — no JavaScript is emitted. Hover, click, and tab through the demos to see them fire.

Variant Fires when Live
hover: Pointer is over the element
focus: Element receives focus (any method)
focus-visible: Keyboard focus only (Tab, not click)
focus-within: Element or any descendant is focused
active: Element is being pressed
visited: Link has been visited Visited link
target: URL fragment matches the element id navigation state
Prefer focus-visible: over focus:. focus-visible skips the state when the user clicks — it only fires on keyboard navigation. This is what you want for accessibility-friendly focus rings.
Section 05 · Form state

Form-state variants

These variants read the browser's native form state. When the input is invalid, when a checkbox is checked, when a field is required — the variant fires automatically.

Variant Fires when Live
disabled: Element has [disabled]
enabled: Element does not have [disabled]
checked: Checkbox or radio is checked
indeterminate: Checkbox is indeterminate (set via JS) set via JS
required: · optional: Field is / isn't required
valid: · invalid: Field passes / fails validation
in-range: · out-of-range: Number input is inside / outside its min-max range values
read-only: · read-write: Field is / isn't editable
placeholder-shown: Input is showing placeholder text
autofill: Browser has autofilled the field autofill state
default: The default button of a form form context

Section 08 · Nth-child

Nth-child variants

Position-based variants accept both numbers and formula syntax (2n+1, 3n, etc.). Use nth-N for a single position and the bracket form for formulas: nth-[2n+1]:.

nth-3:
Item 1
Item 2
Item 3
Item 4
nth-last-1:
Item 1
Item 2
Item 3
Item 4
nth-1: nth-2: nth-3: nth-last-1: nth-last-2: nth-of-type-1: nth-of-type-2: nth-last-of-type-1: nth-[2n+1]: nth-[3n]: nth-last-[2]:
expansion 
/* nth-3:bg-iris-500 */
.nth-3\:bg-iris-500:nth-child(3) { background-color: #8657f7; }

/* nth-[2n+1]:bg-iris-500 — every other element */
.nth-\[2n\+1\]\:bg-iris-500:nth-child(2n+1) { background-color: #8657f7; }

/* nth-last-of-type-1:text-white — last of its tag */
.nth-last-of-type-1\:text-white:nth-last-of-type(1) { color: #fff; }
Section 09 · Relational

Group & peer variants

Group and peer variants let a child or sibling respond to the state of a different element. Mark the parent with .group or the sibling with .peer, then use a relational variant on the element you want to style.

Group — parent state

Hover the card below. The .group parent is the card; the child title uses group-hover: to turn iris.

Peer — sibling state

Peers work on siblings that come after the marked element. The peer must precede the target in the DOM. Below, ticking the checkbox toggles the sibling label.

When the checkbox is checked, the row above changes.
peer-hover: peer-focus: peer-focus-visible: peer-checked: peer-disabled: peer-invalid: peer-valid: peer-required: peer-placeholder-shown: peer-open: peer-odd: peer-even:
Named groups. If you need multiple independent group contexts in the same tree, use group/{name} on the parent and group-hover/{name}: on the child. The engine keeps them separate.
Section 10 · :has()

:has() variants

The has-[selector]: variant applies styles to an element if it contains a matching descendant. This is a huge shift — you can now style parents based on their children without JavaScript.

has-[:checked]: has-[.active]: has-[input:focus]: has-[img]: has-[svg]: has-[>figure]: has-[input:invalid]: group-has-[:checked]: peer-has-[:checked]:
Live demo

The card below turns iris only when it has an input that is focused. Try clicking the field.

Contact form
expansion 
/* has-[:checked]:bg-iris-500 */
.has-\[\:checked\]\:bg-iris-500:has(:checked) {
  background-color: #8657f7;
}
Section 11 · :not()

:not() variant

The not-* variant wraps the utility in :not(selector). Combine with other variants to exclude elements from a rule. Nested variants work — not-hover: means "when NOT hovered."

not-first: not-last: not-disabled: not-hover: not-dark: not-[:checked]: not-[.is-active]:

Section 13 · Container queries

Container queries

Container queries respond to the size of a container element, not the viewport. This is the modern way to build reusable components that adapt to wherever they're placed. First mark an ancestor as a container with @container, then use @sm: through @7xl: on its descendants.

Named containers

Use @container/{name} to give a container a name, then @md/{name}: on descendants to resolve against that specific ancestor. This matters when you have nested containers and need a descendant to respond to a specific one.

named containers

  <h3 class="text-sm @lg/sidebar:text-lg">
    Grows only when the sidebar is ≥ 32rem
  </h3>
</aside>

  <h1 class="text-2xl @md/article:text-4xl">
    Independent of the sidebar
  </h1>

Section 15 · Feature queries

Feature queries

The supports-[...] variant wraps the utility in @supports. This is how you progressively enhance — apply an effect only when the browser can handle it.

supports-[backdrop-filter]: supports-[display:grid]: supports-[container-type:size]: supports-[color:oklch(0_0_0)]:
expansion 
/* supports-[backdrop-filter]:bg-white/60 */
@supports (backdrop-filter: var(--tw)) {
  .supports-\[backdrop-filter\]\:bg-white\/60 {
    background-color: rgb(255 255 255 / 0.6);
  }
}

Section 19 · Arbitrary

Arbitrary variants

For cases the standard variant families don't cover, use bracket syntax. The engine reads the content as-is and builds the selector. When the arbitrary variant contains a &, that's where the utility's selector goes.

[&:nth-child(3)]:

Use any pseudo-class the engine doesn't have a shorthand for.

[mask-type:luminance]

Apply arbitrary property:value as a class itself.

[@supports(display:grid)]:

Wrap in a custom @supports block.

[.js &]:

Conditional on an ancestor class — the & is where the utility selector goes.

example 
<!-- Every third child gets iris text -->
<div class="[&:nth-child(3)]:text-iris-500">...</div>

<!-- Only when JavaScript is on (html.js is the parent) -->
<div class="[.js_&]:block [html:not(.js)_&]:hidden">
  Progressive enhancement
</div>

<!-- Standalone arbitrary property -->
<div class="[mask-type:luminance]"></div>
Spaces become underscores. Because class names can't contain spaces, use _ inside brackets: [.js_&]:. The engine converts underscores back to spaces when emitting the selector.
